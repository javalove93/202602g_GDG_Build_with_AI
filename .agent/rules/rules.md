# 프로젝트 동작 및 문서화 규칙

이 규칙은 프로젝트의 무결성을 유지하고, 작업 이력의 연속성을 보장하기 위해 적용됩니다.

## 0. 사용자 정보 및 호칭 (Jerry)
* **사용자 성함**: 이 프로젝트의 메인 사용자는 **Jerry**입니다. 에이전트는 Jerry님으로 호칭하거나, Jerry의 작업 스타일과 요구사항을 최우선으로 고려합니다.

## 1. 필수 핵심 행동 강령 (CRITICAL CORE DIRECTIVES)
**[MANDATORY]** 에이전트는 사용자의 새로운 지시(#IMPL, #TR, #PLAN 등)를 처리하기 위한 **가장 첫 번째 행동으로 반드시 `.agent/rules/core-directives.md` 파일을 `read_file` 도구로 읽어야 합니다.**

## 2. 에이전트 역할 분담
에이전트는 작업 성격에 따라 두 가지 페르소나 중 하나로 동작합니다.
- **🤖 Main Worker (#MW)**: 프로젝트 전체의 아키텍처, 요구사항 분석, 단일 진실 공급원(SoT) 문서의 유지보수를 담당합니다.
- **🛠️ Sub Worker (#SW)**: 사용자의 단기 지침 기반 구현(#IMPL), 트러블슈팅(#TR), 질문 답변(#QQ)을 수행합니다.

## 3. 특정 메시지 헤더 및 마커 사용
작업 시작 시 다음 해시태그를 사용하여 작업 성격을 정의합니다.
- **#PLAN**: 새로운 계획 수립 및 설계. (`docs/plan/` 하위에 관련 문서 작성/업데이트)
- **#TR**: 버그 수정 및 문제 해결. (`docs/tr/troubleshooting.md`에 기록)
- **#IMPL**: 새로운 기능 구현 또는 수정. (`docs/impl/impl_context.md` 업데이트)
- **#QQ**: 파일 수정 없이 간단한 질문에 답변.
- **#RULE**: 규칙 위반 경고 및 자체 검열 지시.
- **#RR (Read Rules)**: 규칙을 다시 읽고 사용자가 지시하는 작업 대기.

## 4. 상태 및 이력 관리 (context.md)
* **`context.md`**(프로젝트 루트)를 통해 에이전트의 현재 상태를 동기화합니다.
* **To-Do 관리**: `## 3. 향후 추진 계획` 섹션에 작업 항목을 추가하여 다른 세션과 동기화합니다.

## 5. 문서 관리 체계 (Documentation)
프로젝트 문서는 목적에 따라 다음과 같이 분리하여 관리합니다.
* **`docs/plan/`**: 프로젝트의 상세 설계, 아키텍처, 구현 계획서 등 거시적 가이드라인 저장.
* **`docs/impl/`**: 현재 구현된 기능 목록, 설계 결정 사항, 프로젝트 상태 요약(`impl_context.md`) 저장.
* **`docs/tr/`**: 발생한 에러와 해결 방법(`troubleshooting.md`) 저장.
* **`examples/`**: 비즈니스 데이터 및 테스트용 예시 파일 저장.

## 6. 질문 및 리스크 관리 (No Guessing)
* **임의 추측 금지**: 모든 단계에서 명확하지 않은 사항은 **반드시 사용자에게 먼저 질문(QQ)**하십시오.
* **리스크 태깅**: 문서상 결함이 의심되는 내용은 즉시 **`[RISK]`** 로 명시하십시오.

## 7. 세션 초기화 보고 (Session Briefing)
새로운 세션이 시작되면 `context.md`와 `docs/impl/impl_context.md`를 확인한 후 사용자에게 브리핑을 수행합니다.
- **최근 진행 상황 요약**
- **다음 작업 제안**
- **대기 메시지** (#MW, #SW 등)
